# 区域扫描重写

Foundation 使用独立运行时和 `runtime-v2.sqlite`，默认后端仍为 legacy。本文说明区域扫描批次的设计和验收口径；最终通过记录以同一源码快照的构建／测试结果为准。

## 库存怎么算

同一原理图内按 `维度 + 方块实体坐标` 标识物理库存来源，每个来源只贡献一次。多个备货区、多个引用仓库重叠不会重复计入；同时属于备货区和仓库时优先算备货区。不同原理图各自查看共享库存，不增加预留或跨项目独占。

双箱的两个方块实体各读取自己的 27 格，不重复读取整双箱，也不为另一半加载邻区块。箱子里的潜影盒沿用“盒体＋盒内物品”口径。区域重叠与库存新鲜度分别提示：**去重后的库存仍可信，重叠不等于过期。**

## 只观察，不改变世界

- 扫描只访问 `getChunkNow` 返回的已加载区块。
- 只读取已存在的方块实体集合，不调用会加载区块或初始化待加载实体的世界坐标查询。
- 非空 loot table 的容器不调用任何槽位读取或 `isEmpty`，避免提前生成结构战利品；正常玩家开箱后才统计。
- 区块卸载不是拆箱：卸载保留最近观测并标为过期，重新加载后按来源替换，不重复累加。
- 已加载区块里的真实拆箱可以精确扣减，不等待整片区域都加载。
- 世界读取只在服务器线程；存储执行器只接收不可变值，不访问 Minecraft 对象。

扫描按区块索引找到所有相交区域，dirty 事件合并；读取量、区块任务和协作式时间预算限制每 tick 的工作。重扫请求进入同一队列，不在网络 handler 里全区域同步扫描。

超过区块枚举或单源读取上限时，不把部分结果当成完整覆盖：保留最近观测并标为未知／过期，按退避或后续变化再试。单物品堆的潜影盒内容逐槽位计费；过大组件保持 opaque。1.5 ms 是协作式调度期限，不是对任意第三方容器读取耗时的硬保证。

## 未知、过期与已确认

从未观测的区块是未知，不是库存零。卸载、正在刷新或无法安全读取的部分不能作为“准备已确认”；最近观测数量可以继续显示，但必须有警告。

启动新的扫描 epoch 时，旧覆盖先标过期。配置几何修订、区块／dirty 代数、物理来源观测顺序阻止过时结果恢复库存；重命名不丢覆盖，坐标或维度变化重新建立覆盖。

新建区域、移除区域、仓库引用和库存投影通过同一个单写线程与事务；材料、认领、配置和数量不跨修订拼接。schema v3 由现有迁移框架备份后升级；旧 `syncmaterial.db` 不导入、不覆盖、不删除。

## 协议和界面

已发布 Hello 和其它 payload 的字段不变。协议 3 增加一个 `AreaInventorySnapshotS2CPacket`，绑定当前材料目录投递修订和库存序号，表达全材料集、有效备货区／仓库贡献及明确新鲜度。旧响应不携带修订，因此新能力不借旧字段偷偷改变布局。

- 服务端只向支持协议 3 的玩家发新快照，最低兼容版本仍为 1。
- 客户端只接受当前项目／目录及更新的库存序号；目录变化先使旧准备状态失效。
- 协议 1／2 客户端仍可用已有包，但不能把没有权威新鲜度的界面完成状态当作有效备货确认。
- 重叠警告复用成功的区域 LIST 响应消息；下一个空警告快照将其清除，不混进“不可信库存”的 freshness。
- 仓库明细旧包不含维度，因此服务端按玩家当前维度过滤，跨维度旧响应被拒绝；客户端换维度清缓存并重新订阅。
- 界面不改版，只修数据绑定、空警告清除与管理响应路由。

区域与仓库 CRUD 继续对所有玩家开放；校验参数、项目范围和目标存在性，不新增负责人权限限制。

## 验收

本机网络／外置仓库需复制到独立的本地文件系统构建。源码副本和交接记录放持久目录，不以 `/tmp` 作为未提交源码的唯一存放处；测试产物可以重建。所有验收命令在同一个已冻结副本执行：

```bash
JAVA_HOME=<Java25> bash ./gradlew buildAllVersions checkAllVersions \
    testAllClients testOptionalDependencies --no-build-cache
python3 -I scripts/verify_multiversion.py --root . --scope all --strict
```

三节点都需通过共享／平台单测、旧后端／Foundation GameTest、真实客户端与缺依赖启动；新 GameTest 方法的注册、filter 与精确执行数必须一致，空选集或复用旧日志不算成功。

回归重点：重叠去重／备货区优先、跨维度同坐标、跨区块／重复加载／卸载缓存、拆箱、几何变化、未展开 loot 不变、dirty 管线和预算、迁移备份／回滚、旧 epoch／旧目录／旧库存响应拒绝、警告显示与清除。测试数据通过生产仓储创建，不复制一份猜测的当前 schema。

本批不包含负责人批量管理、完整团队搬运、客户端会话全面迁移或删除旧后端，也不授权正式服切换和发布。
